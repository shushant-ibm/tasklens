Fix Log (3 Issues Resolved)

Fix 1 — Wrongly Staged Deleted File (Circular Dependency Risk)
tasklens-workmanager/src/main/kotlin/.../workmanager/WorkerTracing.kt

This file was staged in git (AD status) but had already been deleted on disk. If committed, it would have re-introduced WorkerTracing.kt inside tasklens-workmanager, which would have created a circular dependency. The correct location is tasklens-android/…/android/WorkerTracing.kt. Fixed via git restore --staged.

Fix 2 — Noop Config Parity: 4 Boolean Defaults Wrong
tasklens-noop/src/main/kotlin/.../android/TaskLens.kt

Per AGENTS.md, tasklens-noop must mirror the exact API of tasklens-android. Four boolean constructor parameters in the noop TaskLensConfig had default values of false when the real implementation defaults them to true: captureEnvironment, enableKourierBridge, autoObserveWorkManager, diagnosticsEnabled. All four corrected to true.

Fix 3 — Compile Error: Duplicate Class Name PlatformLimitation
tasklens-core/src/main/kotlin/.../core/PlatformLimitations.kt

Two classes named PlatformLimitation existed in different files within tasklens-core: the canonical data class in Diagnosis.kt (public API) and an internal runtime class in PlatformLimitations.kt. The internal class was renamed to ObservedPlatformLimitation. No external callers referenced the renamed type — confirmed by grep across all modules.
