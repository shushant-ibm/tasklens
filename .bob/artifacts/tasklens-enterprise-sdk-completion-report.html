Key Technical Decisions

  • atomicfu plugin excluded from build graph — atomicfu 0.27.0 Gradle plugin crashes with Kotlin 2.4.10 KGP because KotlinCompilation.getCompileKotlinTask() was removed from the public API. Workaround: plugin declared apply false; the library artifact is still a commonMain dependency and SequenceCounter compiles correctly via the IR compiler without the Gradle plugin transformation.
  • EventType has 32 entries, not 31 — The original ParityTests assertion of 31 was wrong. CUSTOM_BREADCRUMB (entry 32) exists in both the JVM canonical source and the KMP commonMain mirror. Fixed in parity tests to prevent silent drift.
  • KMP compilerOptions DSL, not deprecated jvmToolchain — Used modern kotlin { compilerOptions { jvmTarget.set(...) } } DSL throughout tasklens-core-kmp/build.gradle.kts to avoid deprecation warnings under Kotlin 2.4.x + AGP 9.4.
  • kotlin.time.Instant enforced, not java.time.Instant — All timestamp fields in commonMain use kotlinx-datetime types. This is a hard serialization boundary requirement; mixing types breaks JSON deserialization of stored event blobs.
  • No-op inline trace uses Any receiver, not ListenableWorker — The tasklens-noop module must not depend on tasklens-android. The trace() extension is typed to Any (with inline + zero allocation) to remain API-compatible without importing Android classes.
  • iosX64 tests skipped on Apple Silicon CI — This is expected and correct. The iosX64 klibrary still compiles successfully; only test execution requires an x86_64 Simulator. Apple Silicon CI runners run iosSimulatorArm64 tests instead.
